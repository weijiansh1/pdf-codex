# 和 Codex 一起写报告：coPDF 协作指南

这份指南介绍一种工作方式：你负责研究问题、数据和判断，Codex负责整理内容、处理图表、修改源码和排版；双方围绕同一份本地报告反复修改，最后导出PDF。

界面的具体按钮见 [使用说明](https://github.com/weijiansh1/pdf-codex/blob/main/docs/usage.md)，安装方式以 [仓库首页](https://github.com/weijiansh1/pdf-codex#readme) 的当前发布状态为准。这里重点讲怎样协作。

## 1. 先理解三个角色

| 角色 | 负责什么 |
|---|---|
| 你 | 给出目标、原始材料、实际约束和判断标准，确认数据与最终结论 |
| Codex | 阅读材料、整理结构、计算和绘图、修改正文/公式/样式，并说明改动 |
| coPDF | 展示同一份报告，提供选区、文件、源码、终端、历史和导出入口 |

日常主稿通常是HTML。你在网页上改字，或让Codex修改HTML/CSS，都落在同一份本地报告上；网页更新后可以直接检查。PDF是需要交付时导出的结果，后续改字仍从主稿继续。

## 2. 推荐的一轮协作

1. **先说目标。** 说明这轮完成后应该看到什么。
2. **准备材料。** 给出数据、单位、图片、已有文字或参考样式。
3. **确定范围。** 修改整篇时清除旧选区；改局部时选中对应内容，核对目标卡片。
4. **提交要求。** 在网页Codex终端对话，或在要求框里点“发送给Codex”。
5. **检查结果。** 看正文、图表、公式和页内布局，再给具体反馈。
6. **保存与交付。** 满意后保存；需要交付时重新导出PDF，并打开实际产物检查。

第一次可以先形成完整初稿，后续每轮集中改一个可以检查的目标，例如“补全这张图的单位”“压缩结论”“把这一页字号放大”。

## 3. 开始新报告时，怎样提出要求

一份清楚的初始要求通常包含下面五项：

| 信息 | 示例 |
|---|---|
| 报告目的 | 向同学展示一次实验的主要结果 |
| 内容范围 | 只写数据可视化与分析 |
| 材料 | 当前目录的数据表、装置说明和两张图片 |
| 版式 | 一页横版、适合投影、图中文字要清楚 |
| 判断标准 | 保留全部测量点，结论能对应到图上的变化 |

可以直接这样说：

> 请基于当前报告目录中的数据整理一页横版实验分析。先把原始测量值、单位和计算关系核对清楚，再绘制两幅最能说明结果的图，写出对应分析。正文用较大的字号，导出时保持一页。

如果还没决定该画什么，可以先要求一个具体的分析结果：

> 先根据这些数据提出三种图表方案，说明每幅图能回答什么问题，并推荐其中两种。确认数据关系后再做成报告。

参考报告可以用来说明版式、图表类型和表达深度；当前报告的数据和结论仍以你提供的材料为准。

## 4. 怎样让 Codex 只改一部分

在预览区勾选 **选择内容**，点选段落、公式、图或表，确认目标卡片，再发送修改要求。选择本身不会自动发送消息。

要求里写清三件事：**改哪个对象、改成什么、保留什么。**

例如：

> 只修改选中的分析段落。缩短到三句话，先描述趋势，再解释原因，保留原来的数值和单位。

> 只调整这张图的样式。放大标题、刻度和图例，把图例移到图外右侧，保留所有数据点。

> 修改这个公式后的说明，补充每个符号的物理意义，并统一符号与正文的写法。

如果要改的是整张图的生成代码或整段HTML结构，也可以从 **源码** 里选中相关内容后再交给Codex。

修改整份报告前清除旧选区，核对目标卡片显示的是当前报告，避免要求和当前目标不一致。

## 5. 不满意时，怎样反馈

把反馈落到对象和结果上，通常比反复说“再好一点”更有效。

| 当前问题 | 可以这样反馈 |
|---|---|
| 图中文字太小 | 把三幅图的坐标刻度、轴标题和图例一起放大，保持三幅图字号一致 |
| 内容太挤 | 保留数据和结论，压缩重复说明，为图表增加空间，仍保持一页 |
| 结论太空泛 | 每条结论都对应一个图上的变化或计算结果，写出比较对象和差异 |
| 改动范围太大 | 恢复其他段落，只保留选中段落的修改 |
| 风格不一致 | 统一标题层级、正文大小、图题位置和数字有效位数 |
| 没按参考样式做 | 沿用参考中的字体、留白和表格线条，使用本报告的内容与数据 |

也可以直接指出版式的空间关系：

> 打开侧栏后正文应该跟着变窄，让我能同时看到编辑区和正文。请检查窄窗口下的布局。

> 这一页的结论区太靠下，把上方重复说明缩短，让最后一行在导出PDF里完整显示。

## 6. 数据、图表和公式怎样配合

把原始数值、单位、零点、换算关系和标定条件一起交给Codex。对手写记录或含涂改的数据，先把需要确认的数值核对清楚，再进行计算。

可以把一次分析拆成三个连续结果：

1. **整理数据表。** 显示原始量、单位、换算后的量和使用的公式。
2. **生成图表。** 绘制趋势、对比、拟合或误差图，保留数据点和图例。
3. **写分析。** 说明图表支持的发现，并解释差异与实验条件的关系。

示例：

> 先把原始读数和换算结果做成一张表，确认单位和零点处理。然后画出两种测量方法的结果对比及相对误差，给出拟合关系。最终分析按图上的实际结果写。

公式可以用LaTeX语法输入。HTML公式块即时渲染，普通改字和公式修改不需要等待TeX编译。完整操作见 [使用说明中的文字与公式编辑](https://github.com/weijiansh1/pdf-codex/blob/main/docs/usage.md#5-修改文字公式和排版)。

## 7. 什么时候自己改，什么时候交给 Codex

| 任务 | 方便的做法 |
|---|---|
| 改几个字、标题或一个数值 | 双击网页直接修改 |
| 改一段文字的表达或逻辑 | 选中段落，向Codex描述目标 |
| 改公式本身 | 使用公式编辑器，或从源码修改复杂结构 |
| 调整多张图的大小、配色和字体 | 选中相关图表，或说明整份报告的统一要求 |
| 重新组织章节、补分析或调整全篇版式 | 清除局部选区，明确要求处理当前报告 |
| 撤回一次不合适的修改 | 核对修改历史，使用撤销，再提出新的局部要求 |

同一块内容正在手动编辑时，先保存或取消，再让Codex修改它。这样预览里的草稿和磁盘主稿保持一致。

## 8. 桌面聊天和网页终端的关系

coPDF网页里的Codex终端是独立会话。你在Codex桌面当前聊天说过的要求，不会自动出现在网页终端中；在网页里继续时，把需要的目标和材料说明给这个会话。

推荐日常围绕当前报告在网页终端连续协作：正文、选区和对话在同一处。需要回到桌面聊天处理工程或其他文件时，明确本地报告目录及要继续的任务。

查看同一份本地报告时，磁盘上的更新会反映到网页；必要时点 **刷新预览**。切换会话时先保存已有草稿，再确认正在处理的报告。

## 9. 怎样验收一轮修改

可以按下面的顺序检查：

1. 这轮要求的内容是否已经完成，修改范围是否符合目标。
2. 数值、单位、公式和图表数据是否与原始材料一致。
3. 正文的比较和结论是否能在图表或计算结果中找到依据。
4. 当前窗口里，标题、图题、刻度和正文是否清楚，是否有遮挡或截断。
5. 需要交付时，保存后重新导出，并打开刚生成的PDF核对页数和布局。

若有问题，沿用同一份报告继续提出具体反馈；若一轮修改整体不合适，先通过历史恢复到合适版本，再继续。

## 10. 一段完整的协作示例

**第一轮：形成初稿。**

> 用当前目录的数据写一页横版实验分析，放一张主要趋势图、一张误差图和三条结果分析。先保留完整的数据处理依据。

**第二轮：改图。** 选中趋势图后：

> 把图例移到图外，放大坐标和刻度字体，统一颜色；数据与拟合关系保留。

**第三轮：改分析。** 选中结果段落后：

> 把这段改成三句话，每句对应一个图上的发现，保留比较数值和单位。

**第四轮：交付。**

> 检查整页的字号、图表边界和留白，保持一页横版。保存后导出PDF，我会打开最终文件核对。

这几轮分别产生可检查的内容：先有完整报告，再改图、改文字，最后验收导出文件。
